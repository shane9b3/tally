## HIGH (silently wrong results or data loss)

### H1. ODS import of AOO conditional formats (`style:map`): conditions of de-duplicated automatic styles are dropped and the first style's conditions are applied to the other cells; no first-match semantics
- **Where.** `crates/tally-io-ods/src/styles.rs:82-84` ("Resolved style index → the `style:map`s of the (first) style that resolved to it") and `:249` (`self.style_maps.entry(i).or_insert(maps)`); `crates/tally-io-ods/src/read.rs:239-300` (`legacy_maps`, `stop_if_true: false` at `:286`); `crates/tally-engine/src/condfmt.rs:1590-1600` (`merge_under`, property-wise merge of every matching rule).
- **Repro** (`zz_r3d::d01_stylemap_fixture`, fixture `$S/c3/fx/f01_stylemap.ods`). Three automatic cell styles `ce1`, `ce2`, `ce3` with identical formatting but different `style:map`s (A: `cell-content()<5` → Bold, `cell-content()<10` → Red; B: `cell-content()>[.A1]` → Bold with base B1; C: `cell-content-is-between(1,5)` → Bold, `is-true-formula([.A1]+[.C1]>6)` → Red). Loaded: one conditional format over `A1:C3` with only `ce1`'s two rules; `d01 B1: text="2" bold=Some(true) fill=Some("ff0000ff")`, `d01 B3 (100): bold=None` (AOO: Bold), `d01 C2 (0): bold+red` (AOO: Red only), `d01 A1 (3): bold+red` (AOO: Bold only).
- **AOO.** Style resolution happens per automatic style, each with its own maps; `ScConditionalFormat::GetCellStyle` (`$A/sc/source/core/data/conditio.cxx`, `for (i…) if (ppEntries[i]->IsCellValid(…)) return ppEntries[i]->GetStyle();`) applies **only the first matching** entry's style. `docs/calc-features-inventory.md:256` documents this ("The first matching condition wins").
- **Fix.** Key `style_maps` by the automatic style *name* (before de-duplication) or de-duplicate on `(properties, maps)`; when importing `style:map`s, set `stop_if_true: true` on every rule (or convert each map to a rule chain that stops), so the first match wins as in AOO.

### H2. Criteria, `VALUE` and `DATEVALUE` ignore the document locale: under de-DE `COUNTIF(…;">1,5")` is 0 and `VALUE("1,7")` is `#VALUE!`
- **Where.** `crates/tally-functions/src/criteria.rs:386` (`recognize_input_with(rest, &EN_US, &ctx)`) and `crates/tally-functions/src/coerce.rs:198` (same, used by VALUE/DATEVALUE). The review-1 H2 fix hard-codes `EN_US` instead of the workbook locale (`wb.locale` is what `recognize` uses for typed input).
- **Repro** (`zz_r3d::d03_misc_followups`, document locale de-DE, A1:A3 = 1, 2, `1,7`; A4 = `19.10.2026`, A5 = `1.7.2026`):
  - `=COUNTIF(A1:A3;">1,5")` → **0** (expected 2); `=COUNTIF(A1:A3;">1.5")` → 2 (the en-US form works).
  - `=SUMIF(A4:A5;"<19.10.2026")` → **0** (expected 46204); `=SUMIF(A4:A5;"<10/19/2026")` → 46204.
  - `=VALUE("1,7")` → `#VALUE!`; `=VALUE("19.10.2026")`, `=DATEVALUE("19.10.2026")` → `#VALUE!` (both work with en-US spellings).
- **AOO.** `ScValue` (`$A/sc/source/core/tool/interpr1.cxx`, `pFormatter->IsNumberFormat(aInputString, nFIndex, fVal)`) and the criteria functions use the document's number formatter, i.e. the document locale (review 1 cited `ScCountIf`/`ScSumIf`).
- **Fix.** Pass the workbook locale into `EvalContext` (it already carries the epoch) and use it in `criteria.rs:386` and `coerce.rs:198`; keep the en-US/ISO fallback for `parse_unambiguous`.

### H3. ODS named expressions ignore `table:base-cell-address`, so relative references in names from AOO/LibreOffice files point at the wrong cells
- **Where.** `crates/tally-io-ods/src/content.rs:944-990` (`parse_named_expressions` reads only `table:cell-range-address`/`table:expression`); names are evaluated relative to the using cell with an implicit base of A1 (`crates/tally-engine/src/names.rs:7-16`).
- **Repro** (`zz_r3c::fx01_ods_fixtures`, fixture `f04_names.ods`): `<table:named-expression table:name="Rel" table:base-cell-address="$Sheet1.$C$1" table:expression="of:=[.B1]"/>` with B1 = 10, B2 = 20 and `=Rel` in C1 and C2. Result: `fx01 f04 C1: Number(0.0)`, `C2: Number(0.0)` (the name is treated as "one column to the right of the using cell"). AOO: 10 and 20 (`ScRangeData::IsReference(aRange, aPos)` computes relative references from the base cell, see the comment in `ScIndirect`, `$A/sc/source/core/tool/interpr1.cxx:7000-7010`, "This is the usual way to treat named ranges containing relative references").
- **Impact.** Any imported name with relative references (the classic "cell above/left" names) evaluates silently wrong; a Tally re-save then writes the wrong base (`$Sheet1.$A$1`) and makes it permanent.
- **Fix.** On import, shift each relative reference by `(A1 − base)` so the expression is correct for Tally's A1 base; on export, write `table:base-cell-address` of the (sheet's) A1, which the writer already does. Document in `docs/file-formats.md` that Tally has no base cell.

### H4. ODS import silently drops names that would be cell references in Excel's 16 384-column grid (`Rel2`, `Tax1`), leaving `#NAME?` with no warning
- **Where.** `crates/tally-engine/src/names.rs:293-335` (`validate_name`, `"is a cell reference or not a valid name"`), applied to imported names.
- **Repro** (`fx01_ods_fixtures`, `f04_names.ods`): `<table:named-expression table:name="Rel2" … expression="of:=[.A1]*100"/>` and `=Rel2` in B4 → `fx01 f04 B4: Error(Name)`; the name list after load has no `Rel2`; `info.warnings = []`.
- **AOO.** AOO 4.1 has 1024 columns (AMJ), so `REL2`, `TAX1`, `ZZZ9` … are legal names there and occur in real files; `ScRangeData` only rejects names that parse as references in *its* grid.
- **Fix.** Accept such names on import (keep them unparsable from the formula bar if you must, or allow any name that is not a valid reference in the *file's* grid) and at minimum report a warning in `WorkbookInfo.warnings` when a name is dropped.

### M4. Conditional formats and validations do not follow cells on copy/paste, cut/paste (`MoveRange`) or sort; notes are not copied by paste
- **Where.** `crates/tally-engine/src/moves.rs`, `clipboard.rs`, `sort.rs` touch neither `meta.cond_formats` nor `meta.validations` (grep); `annotations.rs` moves notes only for insert/delete/move/sort.

### M5. List validation: inline items that parse as numbers do not match typed numbers
- **Where.** `crates/tally-engine/src/validation.rs:474-485` (string items compared as text; a number only matches if its general string equals the item text).
- **Repro** (`zz_r3c::ms01_misc`, list `1.50, 10, x, 1,000`): entering `1.5` → `validation:bad`, `1.50` → `validation:bad` (typed 1.50 is the number 1.5), `'1.50` (text) → accepted; `1000` and `1,000` → rejected. `zz_r3a::va01`: list `1, Two, 1.50`: `1.0` accepted, `1.5` and `1.50` rejected.
- **AOO.** `ScValidationData::IsListValid` (`$A/sc/source/core/data/validat.cxx:856-895`): each string token is converted with `IsNumberFormat(*pString, nFormat, fValue)` and numeric tokens are added as doubles (`aCondTokArr.AddDouble(fValue)`), so 1.50 matches 1.5.
- **Fix.** Recognise each inline item with the document locale once (`recognize_input_with`) and compare numerically when both sides are numbers.

### M6. Number-format codes in `TEXT()` are not localized: under de-DE `=TEXT(1.7;"0,00")` gives `002`
- **Where.** Format codes are always parsed with en-US separators (`tally_numfmt::parse_format`, used by TEXT and `SetNumberFormat`); the formula dialect localizes the list separator but not the decimal separator (`docs/api.md:230` documents the `.` decision for formulas).
- **Repro** (`zz_r3d::d03`, de-DE): `=TEXT(1.7;"0,00")` → `002`; `=TEXT(1.7;"0.00")` → `1.70` (en-US output in a German document); `=TEXT(DATE(2026;10;19);"TT.MM.JJJJ")` → `TT.10.JJJJ`; `=COUNTIF(A1:A3;1,7)` and `=TEXT(1,7;"0,00")` → `Err:504`.
- **AOO.** `ScText` (`$A/sc/source/core/tool/interpr1.cxx`, `eCellLang = …ATTR_LANGUAGE_FORMAT…; pFormatter->GetPreviewStringGuess(sFormatString, fVal, aResult, &pColor, eCellLang)`) parses the code in the cell's language, so `"0,00"` in a German document gives `1,70`; the compiler reads decimals with the locale separator unless English symbols are active (`$A/sc/source/core/tool/compiler.cxx:1971`, `cDecSep = (mxSymbols->isEnglish() ? '.' : …getNumDecimalSep())`).
- **Action.** Either localize codes in TEXT (map the locale's decimal/group chars to `.`/`,` before parsing, and accept the localized keyword set) or document clearly that format codes and formula literals are en-US everywhere; note the inconsistency that `;` *is* localized.

### M7. `set_locale("de-CH")` (and any unknown region) silently falls back to the language's locale
- **Where.** `crates/tally-numfmt/src/locale.rs:390-401` (`locale_by_tag`: unknown region → first locale with the same language).
- **Repro** (`zz_r3c::lc02_locales_fresh`): `set_locale("de-CH")` succeeds; typing `1.5` gives the **date 01.05.2026** and `1'234.56` is text; `General` shows `1234,5`, currency `€`. Swiss German uses `.` as decimal, `'` as group separator and CHF. `pt-BR` also "works" (as nothing) — it fails cleanly, which is better.

### M8. ODS sheet/structure protection is written with SHA-256, which AOO 4.1 cannot verify
- **Where.** `crates/tally-engine/src/protection.rs:403-416` (`new_protection` always SHA-256 + `xmldsig#sha256` URL in ODS).
- **Repro** (`zz_r3b::pr02_protection_roundtrip`): `table:protection-key="XohImNooBHFR0OVvjcYpJ3NgPQ1qq73WKhHvch0VQtg=" table:protection-key-digest-algorithm="http://www.w3.org/2000/09/xmldsig#sha256"`. ## LOW (cosmetic, edge, docs)

- **`INDIRECT("B2";0)` and unparsable text give `#REF!`**, AOO gives `Err:502` (`PushIllegalArgument` at the end of `ScIndirect`, `$A/sc/source/core/tool/interpr1.cxx:7035`). `=INDIRECT("foo")` → `#REF!` likewise.
- **Cell-value CF with a text operand on a number**: `Lt "m"` on 5 → true (`cf10`); AOO `ScConditionEntry::IsValid` returns false for every operator except NotEqual when `bIsStr1` (`$A/sc/source/core/data/conditio.cxx`, "wenn auf String getestet wird, bei Zahlen immer sal_False, ausser bei ungleich").
- **Duplicate CF compares bit patterns**: `0.1` and `=0.3-0.2` are not duplicates (`cf06`); Excel compares at 15 digits. Errors are duplicates of each other (fine).
- **CF "date is" weeks start on Sunday** regardless of locale (`cf08`: a Sunday is "this week" on a Tuesday); AOO 4.1 has no date rules; Excel uses Sunday, LibreOffice Monday. Document.
- **CF after Clear All stays** (`d03`): AOO's Delete Contents "all" removes attributes including the conditional format; Excel's Clear All removes CF.
- **Text-length validation measures the formatted number** (`12.50` typed → length 4, AOO uses the typed string, length 5; `va02`).
- **Lazy AutoFilter** (`rv01`): editing does not re-filter (as documented and as AOO); inserting a row inside the filtered range re-applies the filter so the new empty row is hidden (Excel leaves it visible); sorting a filtered range leaves the hidden set stale (rows 2–3 stay hidden although they now hold 9 and 5). Acceptable per the module doc, but the sort case deserves an automatic refresh or a note.
- **`SUM("3")` = 3** (documented in `docs/contributing-functions.md:141`); AOO's `IterateParameters` gives `#VALUE!` for a direct string in SUM/AVERAGE/PRODUCT (`$A/sc/source/core/tool/interpr1.cxx:3396-3425`, `SetError(errNoValue)`). `=SUM("1.5")` → `#VALUE!` ✓, `="1.5"+1` → `#VALUE!` ✓, `="3"+1` → 4 ✓ (AOO `ConvertStringToValue`, integer-only), `="2026-01-01"+1` → 46024 ✓ (ISO date branch).
- **Goal seek reports success for asymptotic targets**: `EXP(A1)=0` → found, A1 = −21.18 (`|f| = 6e-10 < 1e-9`); `1/A1 = 0` → found, A1 = 1.14e9; and fails to converge on `A1*1e12 = 1` (cancellation at 1e-12). AOO's solver also uses an absolute epsilon, so the first two are probably identical there (unconfirmed).
- **Header/footer**: `&[FILE]` is written to ODS as `<text:title>` (`crates/tally-io-ods/src/v03.rs:1710`); AOO uses `<text:file-name>` for the file name and `<text:title>` for the document title. `&[TAB]` is not a Tally code (`&[SHEET]` is; XLSX `&A` ✓). `PageSetupDto.row_breaks/col_breaks` are reported by `page_setup` but ignored by `SetPageSetup` (`pagesetup.rs:127-210`); breaks only via `SetPageBreak`. Document the asymmetry.
- **ODS fit-to-pages** is written as `loext:scale-to-X/Y` (LibreOffice extension); AOO 4.1 knows only `style:scale-to`/`style:scale-to-pages`, so a 1 × 3 fit prints at 100 % there.
- **XLSX inline list validation**: an item containing a comma (`b,c`) comes back as two items (`va04`); OOXML cannot represent it — warn on save.
- **ODS relative named range** written as `table:cell-range-address=".A1"` (no sheet) for `RelN = A1` (`nm02`); AOO writes `$Sheet1.A1`. Whether AOO parses the sheet-less form is unconfirmed.
- **`SUBTOTAL(101–111)` accepted** (Excel codes; AOO `Err:502`), noted in review 2.
- **Limits**: `MAX_TEXT` is 64 KiB *bytes* (`limits.rs:29`, checked with `text.len()` at `:59`); AOO's limit is 65 535 UTF-16 units, so long non-ASCII texts are rejected earlier here (a 50 k-character ASCII cell is accepted). A 100-column TSV paste is fine (`MAX_TSV` 64 MiB, `MAX_RANGES` 10 000).
- **de-DE accepts `TRUE`/`FALSE` as booleans** in addition to `WAHR`/`FALSCH` (`recognize.rs:97-104`); AOO only accepts the localized names. Harmless.
- **AOO row default**: Tally's default row is 24 px on screen but is saved as `0.452cm` with `use-optimal-row-height="true"` (`af01`), which AOO re-measures; fitted rows are saved with their size and `false` ✓.
