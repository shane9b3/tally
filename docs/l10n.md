# Localisation (`crates/tally-l10n`)

Wave 5 §4 item 47, FN part. `tally-l10n` holds the language data that
the formula layer and the UI need: localized function names, boolean
literals and UI strings for **en-US, de-DE, fr-FR, es-ES**. It depends on
`serde` only, so every crate (engine, formula, API, desktop shell) can use
it without pulling in the function library.

What it does **not** do: the formula dialect (argument separator `;`,
decimal separator `,`, array separators) belongs to `tally-formula`'s
locale-aware parser/printer (ENG); menu wiring and the `i18n/` JSON used
by the React app belong to UI (W5-6E), which can copy `ui/*.json` or load
them through the API.

## API

```rust
use tally_l10n::{Locale, locales, localized_name, canonical_name,
                 localized_bool, parse_bool, t};

Locale::parse("de-AT")                    // Some(Locale::De): by language, any region
Locale::De.tag()                          // "de-DE"
locales()                                 // [En, De, Fr, Es]

localized_name(Locale::De, "SUM")         // "SUMME"
localized_name(Locale::Fr, "MAX")         // "MAX" (same as English)
canonical_name(Locale::Es, "buscarv")     // Some("VLOOKUP") — case-insensitive
canonical_name(Locale::Es, "DIA")         // Some("DAY")     — accent-insensitive fallback
canonical_name(Locale::De, "SUMA")        // None            — Spanish name in German

localized_bool(Locale::Fr, true)          // "VRAI"
parse_bool(Locale::De, "falsch")          // Some(false); "FALSE" is accepted everywhere

t(Locale::De, "cmd.edit.undo")            // "Rückgängig"
t(Locale::De, "no.such.key")              // "no.such.key" (falls back to en, then the key)
```

`Locale` serializes as its tag (`"de-DE"`). `function_names(locale)` and
`unverified(locale)` expose the raw tables; `ui_keys()` lists the English
keys.

### Lookup rules

- **Canonical → localized**: the table entry, else the canonical name
  itself (names identical to English are not stored).
- **Localized → canonical**: upper-cased exact match first (Unicode-aware,
  so `zählenwenn` finds `ZÄHLENWENN`); then an accent-folded match
  (`A` for `ÀÁÂÃÄÅ`, `E` for `ÈÉÊË`, …, `Ñ` kept) so both `DÍA` and `DIA`
  resolve. Canonical names the locale keeps unchanged resolve too, so a
  German document can use `MAX` but not `SUMA`.
- No cross-locale acceptance: AOO does not accept English names in a
  localized UI unless "Use English function names" is on; that switch is
  the parser's, which then uses `Locale::En`.

## Function names

`src/names/{de,fr,es}.rs`: `NAMES: &[(canonical, localized)]` in
master-list order plus `UNVERIFIED: &[&str]`. `src/names/mod.rs` has the
408 canonical names (`CANONICAL`), which `tally-functions`'
`tests/registry.rs` compares with the registry.

| Locale | Localized (differ from English) | Identical to English | Unverified |
|---|---|---|---|
| de-DE | 328 | 80 | 2 |
| fr-FR | 317 | 91 | 5 |
| es-ES | 341 | 67 | 10 |

The spellings follow Apache OpenOffice 4.1 / LibreOffice (which share
them for these three languages): `SUM` → `SUMME`/`SOMME`/`SUMA`,
`AVERAGE` → `MITTELWERT`/`MOYENNE`/`PROMEDIO`, `IF` → `WENN`/`SI`/`SI`,
`VLOOKUP` → `SVERWEIS`/`RECHERCHEV`/`BUSCARV`. The Analysis add-in
functions that carry an `_ADD` suffix in English keep the suffix on the
localized base name (`KALENDERWOCHE_ADD`, `NO.SEMAINE_ADD`,
`SEM.DEL.AÑO_ADD`). Excel-compatible clashes are per locale: Spanish
`DECIMAL` is `FIXED`, Spanish `DECIMAL` (the base-conversion function) is
`CONV.DECIMAL`; French `CONVERT` is the add-in `CONVERT_ADD`, the euro
`CONVERT` is `CONVERTIR`.

**Spanish accents.** LibreOffice's Spanish names carry accents in places
(`DÍA`, `AÑO`); the tables use the unaccented Excel-compatible forms
except for `Ñ`, and lookups fold accents, so both spellings parse.
Printing uses the table's form.

**Unverified entries** were written from memory of the AOO/LibreOffice
lists rather than checked against `extras/l10n/source/<lang>/localize.sdf`
(the owner's AOO checkout, `cargo xtask gen-function-names` in the wave-5
plan). They are: de `WEEKNUM_ADD`, `DURATION_ADD`; fr `CHISQDIST`,
`CHISQINV`, `WEEKNUM_ADD`, `DURATION_ADD`, `MONTHS` (kept as English, the
French `MOIS` would clash with `MONTH`); es `TIME`, `WEEKNUM`, `DURATION`,
`CHISQDIST`, `CHISQINV`, `ARABIC`, `WEEKNUM_ADD`, `CONVERT_ADD`,
`DURATION_ADD`, `ISOWEEKNUM`. Verifying one means editing the table,
removing the name from `UNVERIFIED` and running `cargo test -p tally-l10n`
(the bijectivity test catches clashes).

### Tests (`cargo test -p tally-l10n`)

- `bijective_per_locale`: no localized name used twice, none maps to
  itself, none shadows a canonical name the locale keeps unchanged, and
  every one of the 408 names round-trips `localized_name` →
  `canonical_name` in every locale.
- `coverage_counts`: 408 canonical names, ≥300 localized per locale,
  `UNVERIFIED` entries are real names.
- `spot_checks`: the examples above, case/accent/whitespace tolerance,
  cross-locale rejection, the Spanish `DECIMAL` clash.
- `booleans`, `serde_tags`, `locale_parsing_and_tags`.

`tally-functions` adds `localized_names_cover_the_registry`
(tests/registry.rs): every registered function is in `CANONICAL` and
resolves in every locale; nothing in `CANONICAL` is unregistered.

## UI strings

`ui/{en,de,fr,es}.json`: flat objects of `"key": "text"`, embedded with
`include_str!` and read by a small built-in flat-JSON reader (no JSON
crate). 673 keys per language, the same set in each (the test
`every_ui_key_in_every_language` enforces it). Placeholders are
`{name}` and are the caller's to substitute.

Key groups: `app.*`, `menu.*` (menu bar and submenus), `cmd.<command id>`
(every id in `packages/app/src/commands.ts` plus the wave-5 commands),
`toolbar.*`, `dialog.*` (common buttons and prompts), `sort.*`, `find.*`,
`paste.*`, `names.*`, `cf.*`, `validation.*`, `goalSeek.*`, `solver.*`,
`scenario.*`, `multiOps.*`, `subtotals.*`, `consolidate.*`,
`textToColumns.*`, `duplicates.*`, `pivot.*`, `wizard.*`, `category.*`
(the 11 function categories), `fmt.*` (number formats), `cells.*`,
`sheet.*`, `status.*`, `error.*` (formula and file errors), `chart.*`,
`print.*`, `options.*`, `navigator.*`, `styles.*`, `templates.*`,
`glance.*`, `note.*`, `hyperlink.*`, `protect.*`, `properties.*`,
`shortcuts.*`, `autofilter.*`, `outline.*`, `clipboard.*`, `undo.*`,
`a11y.*`.

To add a key: add it to all four files (the test fails otherwise). Keys
are dotted lower camel case; values are plain text (JSON escapes are
honoured).

## Adding a locale

1. `src/names/<lang>.rs` with `NAMES` and `UNVERIFIED`; `pub mod` it in
   `names/mod.rs`.
2. A variant in `Locale` (tag, language, `parse`), an arm in
   `function_names`, `unverified`, `bool_literals`, and `UI_LOCALES` with
   the new `ui/<lang>.json`.
3. Bump the `[Tables; N]` / `[HashMap; N]` sizes; the tests cover the rest.

## UI wiring (W5-6E)

- `packages/app/src/i18n/{de,fr,es}.json` are copies of `ui/*.json`
  (`packages/app/test/w56i18n.test.ts` fails when they drift);
  `functionNames.json` is generated from `src/names/*.rs` by the same test's
  rule. `setUiLanguage()` installs a table through `t()` and bumps a revision
  the chrome subscribes to; the desktop shell rebuilds the native menu
  (`set_ui_language`, `apps/desktop/src-tauri/src/l10n.rs`).
- Command titles go through `t("cmd.<id>")` (`localizeTitles` in
  `commands.ts`); keys the tables do not have yet are listed in
  `w56i18n.test.ts` (`PENDING_KEYS`) and fall back to English.
- Function names are localized for display only (`formulaNames.ts`): the
  editor, the autocomplete and the Function Wizard show the document locale's
  spelling and commits are translated back to the canonical names the engine
  parses. The formula dialect (`;` vs `,`) stays the engine's.
