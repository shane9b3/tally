# Function Wizard metadata

What `tally-functions` exposes for the Function Wizard (⌘F2, wave 5 §4
item 19), formula autocomplete and the assist layer, and where each piece
comes from. The engine lead maps `FunctionMeta` onto the API DTO
(`FunctionInfo.params` and friends); the UI never reads the registry
directly.

## `FunctionMeta`

```rust
use tally_functions::{function_meta, FunctionMeta, ParamMeta, LAST_USED_DEFAULT};

let all: Vec<FunctionMeta> = function_meta();        // 408 entries, registration order
```

```rust
#[serde(rename_all = "camelCase")]
pub struct FunctionMeta {
    pub name: String,            // "SUMIF"
    pub category: String,        // AOO wizard name: "Mathematical", "Date&Time", "Add-in"
    pub params: Vec<ParamMeta>,  // declared parameters
    pub min_args: u8,            // arity (255 = unbounded max)
    pub max_args: u8,
    pub help: String,            // one line
    pub example: String,         // "=SUMIF(A1:A10;\">5\";B1:B10)"
    pub extension: bool,         // not in AOO 4.1 (IFERROR, IFNA, ISOWEEKNUM, NUMBERVALUE)
    pub odf_name: String,        // "COM.MICROSOFT.IFERROR"
    pub ooxml_name: Option<String>, // "_xlfn.IFS"; None = same as name or Excel lacks it
}

pub struct ParamMeta {
    pub name: String,     // "sum_range"
    pub kind: String,     // ParamKind::name(): number integer text bool any numberSeq
                          //   valueSeq reference array criteria lazy
    pub optional: bool,
    pub repeat: bool,     // trailing repeating group (SUM(number; ...))
}
```

Both types derive `Serialize`/`Deserialize` (camelCase keys: `minArgs`,
`odfName`, `ooxmlName`). `Registry::meta()` gives the same for a custom
registry; `FunctionMeta::from_def(&FunctionDef)` for one definition.

### How the wizard should use it

- **Categories**: group by `category`; the order is
  `tally_functions::Category::ALL` (AOO wizard order, Database first,
  Add-in last). Localized category labels are UI strings
  (`category.database` … `category.addIn` in `tally-l10n`).
- **Last Used**: `LAST_USED_DEFAULT` is `["SUM", "AVERAGE", "MIN", "MAX",
  "IF"]`, AOO's list for a fresh profile. The UI persists its own list
  after that.
- **Argument fields**: show `params` in order. A `repeat` group (the
  trailing params with `repeat: true`) is shown as many times as the user
  fills it, cycling through the group (`SUMIFS` repeats
  `criteria_range; criteria`, `GETPIVOTDATA` repeats `field; item`). Use
  `min_args`/`max_args` for the hard limits; a few functions override the
  derived arity (`CHOOSE` 2..31, `GETPIVOTDATA` 2..30).
- **Kinds**: `reference` and `array` fields want point mode; `numberSeq`
  and `valueSeq` accept anything; `lazy` is evaluated by the function
  itself (IF branches, MULTIPLE.OPERATIONS cells) and should be shown as
  "any".
- **Description and example**: `help` is the one-liner shown under the
  function list; `example` is a complete formula in the en-US UI dialect
  (`;` separators, `"` strings, `A1:A10` references) that the wizard can
  show as a hint or insert as a starting point. In a localized UI, map the
  function name with `tally_l10n::localized_name` and let the formula
  dialect layer swap separators.
- **Names in files**: `odf_name` / `ooxml_name` are for importers and
  exporters, not for display.

## Where the data lives

| Field | Source |
|---|---|
| `name`, `category`, `params`, arity, `odf_name`, `extension`, `help` | the `FunctionDef` in `crates/tally-functions/src/categories/<category>/<family>.rs` |
| `ooxml_name` | `categories/ooxml.rs` (one table, mirrors `docs/functions/master-list.toml`) |
| `example` | `categories/examples.rs`, **generated** — see below |

### Examples

`crates/tally-functions/src/categories/examples.rs` is generated by

```sh
python3 -I docs/functions/gen-examples.py          # writes the file
python3 -I docs/functions/gen-examples.py --check  # CI: fails if stale
```

The script holds a curated table (one realistic call per function; the
sheet convention is A1:A10 and B1:B10 numbers, C1:C10 text, dates in
A1/B1) and checks every entry against `docs/calc-functions.json` and the
master list: the name must exist, the argument count must be within the
arity, quotes must balance. A function without a curated example gets a
type-driven fallback and a warning, so a new registration never ships
without one. The generated table is applied by `examples::apply` after all
categories registered (`FunctionDef::example` is `""` until then); an
unknown name in the table is recorded as a registry conflict with
`table: "example"`, which `core_functions_registered_without_conflicts`
reports.

Tests: `meta::tests::covers_the_registry` (every function has help and an
example that calls it), `sumif_shape`, `serde_camel_case_round_trip`,
`last_used_default_names_exist`.

## Adding a function

Nothing extra: register the `FunctionDef` with `.help(..)`, add a line to
`EXAMPLES` in `gen-examples.py`, regenerate. `FunctionMeta` picks it up.
